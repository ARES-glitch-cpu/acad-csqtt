# CSQTT — коленка для Windows 10 x64

Минимальный клиент с нативным окном: сервер csqtt, пароль, хеши звонков VK и корпоративный HTTP-прокси с Basic-авторизацией. Поднимает **SOCKS5 `127.0.0.1:1080`** и **HTTP `127.0.0.1:8080`**. Не требует Python на целевом компьютере, прав администратора, Wintun или изменения системных маршрутов.

## Быстрый запуск

1. Распакуйте **`CSQTT-Kolenka-Win10-x64.zip` целиком** в отдельную папку.
2. Запустите **`CSQTT-Kolenka.exe`**. Папки `bin` и `_internal` должны оставаться рядом.
3. Введите **адрес и порт вашего сервера csqtt**, **пароль пользователя csqtt**, **хеши VK** (до 6, можно полными ссылками `/call/join/`). Это не SSH-пароль и не пароль панели управления.
4. Корпоративный прокси: **`10.0.0.1:3128`**. Введите логин и пароль прокси в отдельные поля. Поддерживается **HTTP Basic**.
5. При необходимости нажмите **«Проверить CONNECT :443»**, затем **«Подключить»**. Проверка CONNECT без заданного TURN-хоста обращается к `dns.google:443` и проверяет только корпоративный прокси.
6. После получения конфигурации и готовности потока автоматически стартуют локальные прокси и проверка внешнего IP. Статус различает запуск прокси и подтверждённый доступ в интернет.
7. Укажите локальный прокси в нужном приложении. Кнопка **«Отключить»** и закрытие окна завершают дочерние процессы.

**Firefox:** Настройки → Настройки сети → ручная настройка → SOCKS `127.0.0.1`, порт `1080`, SOCKS v5; включить DNS через SOCKS v5. Альтернатива: HTTP-прокси `127.0.0.1:8080`, использовать также для HTTPS.

Проверка из PowerShell/командной строки:

```powershell
curl.exe --proxy socks5h://127.0.0.1:1080 https://api.ipify.org
curl.exe --proxy http://127.0.0.1:8080 https://api.ipify.org
```

Системный прокси Windows клиент автоматически не меняет. В этой версии через туннель идут приложения, явно использующие локальный прокси. SOCKS поддерживает TCP CONNECT; UDP ASSOCIATE и IPv6 не реализованы.

## Как устроено подключение

```text
Приложение → SOCKS5 / HTTP на 127.0.0.1
           → пользовательский TCP/IP-стек
           → локальный UDP с IP-пакетами, только 127.0.0.1
           → ядро CSQTT
           → TCP к корпоративному HTTP-прокси 10.0.0.1:3128
           → CONNECT <TURN-хост>:443 с авторизацией
           → TURN по TCP или TLS в зависимости от URI VK
           → ваш сервер csqtt → интернет
```

**С компьютера наружу транспорт — TCP через корпоративный прокси.** Локальный UDP между двумя процессами не выходит за пределы компьютера. Участок TURN → сервер работает по протоколу csqtt; корпоративный прокси его не видит.

Порт `443` фиксируется **для TURN**, а не для адреса вашего сервера csqtt. В поле сервера нужно вводить реальный порт из его настроек. Порт корпоративного HTTP-прокси остаётся `3128`.

Ядро дополнено HTTP CONNECT перед TURN/TCP/TLS. Запросы API VK и получение первоначального DNS через HTTPS также направляются через этот прокси. При недоступности прокси перехода на прямое подключение или TURN/UDP нет. DNS внутри пользовательского TCP/IP-стека передаётся в туннеле к DNS, полученному от сервера.

Публичный API DNS `dns.google:443` используется только ядром при необходимости разрешить доменное имя до установления туннеля. Домен сервера и TURN должен разрешаться в IPv4. Обычный NekoBox не реализует протокол csqtt, поэтому здесь используется исходное ядро csqtt и отдельный пользовательский TCP/IP-стек.

## Дополнительные параметры

- **TURN-хост:** необязательный IPv4/домен без схемы и порта. Пустое поле использует адреса из ответа VK. Переопределение имеет смысл только для TURN-сервера, принимающего выданные VK учётные данные и TCP на 443. Указывать здесь обычный VPS csqtt нельзя.
- **Workers:** по умолчанию 6; можно увеличить после успешного подключения.
- **Обфускация:** `unified` по умолчанию; должна соответствовать серверу.
- **SRTP:** `auto` по умолчанию, также доступны `wrap` и `dtls`. Внутренний DTLS в csqtt не меняет внешний транспорт TCP.
- **Поколение / Salt:** заполните, если они выданы сервером; иначе `0` и пустое значение.
- **Запомнить профиль:** все поля сохраняются в `%LOCALAPPDATA%\CSQTT-Kolenka\profile.dat`, зашифрованном Windows DPAPI для текущего пользователя. В portable-архив профиль не включается. При снятой галочке и следующем подключении сохранённый профиль удаляется.

Пароли передаются ядру в окружении дочернего процесса, а не в аргументах запуска. Журнал существует в памяти окна; пароли и полные/короткие хеши маскируются. Учётные данные не вшиты в исходники или исполняемый файл.

## Если подключения нет

- **407:** неверные логин/пароль либо прокси требует NTLM/Kerberos. Эта версия поддерживает Basic. Ошибка 407 может появиться и при обращении API VK через прокси.
- **403 / CONNECT rejected:** прокси запрещает конкретный TURN/API/DNS-хост или порт. Разрешённый порт 443 сам по себе не гарантирует доступ к любому хосту или протоколу на нём.
- **TURN connect / allocation:** выбранный TURN должен действительно обслуживать TCP/TLS на 443. Произвольный UDP TURN нельзя превратить в TCP простым изменением порта.
- **Ошибки VK / CAPTCHA:** хеш может быть недействителен, звонок завершён, API ограничен или нужна капча. Используется автоматическая авторизация исходного ядра; Android WebView и ручное решение капчи в этой оболочке не реализованы.
- **Нет TUNCONF / READY:** проверьте адрес сервера, пароль csqtt, обфускацию, поколение/Salt и журнал ядра. Наличие открытого локального порта ещё не означает рабочий интернет.
- **Порт занят:** выберите другие разные локальные порты; слушатели привязаны только к loopback.

## Сборка и проверки

Исходники оболочки — `app.py`; помощник SOCKS/HTTP и IP-стек — `packet-proxy/`; адаптированное ядро — `core/rust-client/`. Исходная база взята из предоставленного архива `csqtt-2.5.0.7z`. Готовый `client.exe` из архива не используется: ядро пересобирается из исходников.

Нужны Windows x64, Python 3.14 + PyInstaller, Go 1.27, Rust 1.97.1 и MSVC Build Tools. При наличии `.tools/cargo` и `.tools/rustup` скрипт использует локальный Rust.

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
python -m unittest -v test_app
cd packet-proxy
go test -v ./...
```

Тесты проверяют CONNECT с Basic, ошибки авторизации, DPAPI, фиксированный TCP/443, SOCKS и HTTP через два связанных пользовательских IP-стека, обработку данных сразу после CONNECT и отказ UDP ASSOCIATE. Они не заменяют проверку с реальным сервером csqtt и корпоративным прокси.
